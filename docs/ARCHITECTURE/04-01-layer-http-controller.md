# 4.1 Lapisan HTTP — `app/controller/`

> Bagian dari [dokumentasi arsitektur](../ARCHITECTURE.md) · Spesifikasi: [SPECS.md](../SPECS.md) · Panduan operasional: [DETAILS.md](../../DETAILS.md)

Controller hanya **mediator**: tidak memuat logika bisnis, tidak menyimpan state di properti (Webman persistent → `controller_reuse=false`), dan **tidak** memanggil `session()`/`request()` di konstruktor.

| Controller | Tanggung jawab |
|---|---|
| `AuthController` | Login/logout, session, regenerasi session id (anti fixation), migrasi kepemilikan app lama (best-effort). **Langkah kedua 2FA** (§5.5b): `twoFactorForm()` (`GET /login/2fa`) & `twoFactorVerify()` (`POST /login/2fa`) memakai session `2fa_pending` (`user_id`/`created_at`/`attempts`/`redirect`), validasi TTL `PENDING_TTL` + batas `MAX_ATTEMPTS`, verifikasi TOTP/kode pemulihan lewat `TwoFactorService::verifyLoginCode()`; `session['user']` **baru** diisi setelah kode lolos |
| `app/*` (`app\controller\app`) | Fitur app: daftar & impor, detail/versi/status, wizard create (repo/compose/template), deploy, domain, env, compose, container (network/nama/ports/limits), akses. 11 controller konkret + 2 base abstract — peta per kelas & method di [§4.1a](#41a-peta-controller-per-domain). |
| `TerminalController` | Terminal container (`docker exec`): buka sesi interaktif (open), stream output (SSE), kirim input, tutup sesi, dan one-shot run command; container divalidasi milik app **dan** user berhak (ability `terminal`); audit log ke `runtime/logs/terminal/` |
| `LogController` | Log container app (`docker logs`) untuk popup modal di detail app: `GET /api/apps/{id}/logs?container=&tail=`; ability `logs` (Viewer ke atas); nama container selalu divalidasi milik app (`AppContainers::resolve`) sebelum menyentuh Engine. Juga **log deploy on-demand**: `GET /api/apps/{id}/deploy-log?offset=N[&tail=1]` → teks ≤256 KiB + `X-Rames-Offset` (pembacaan via `DeployLog`; ability `logs`) |
| `FileController` | File manager container (§5.16): jelajah/`read`/`write`/`mkdir`/`rename`/`delete`/`upload`/`download`/`extract` untuk container app yang **berjalan**; ability `files` (operator+); container divalidasi `AppContainers::resolve` (jalur sama dengan `TerminalController`); semua logika bisnis di `app\library\Files\*` (controller hanya mediator — envelope `{code:0,data}` / `{code:<status>,msg}`, audit ke `runtime/logs/files/`). **Multi-server (F3b, §5.29)**: app di server `kind=agent` dijalankan **di agent** (`AgentDeployer::file*()` → `/files/*` agent; Engine host control plane tidak disentuh) — envelope agent diteruskan apa adanya (kode domain 409/413/415/404), unduhan/unggahan **streaming** dengan plafon `AgentDeployer::MAX_TRANSFER_BYTES` |
| `NginxController` | **Halaman Config `/nginx`** — empat tab: **Update Rames** (panel self-update, §5.14), **Nginx** (status reload Nginx host terakhir + tombol Reload), **Template** (katalog template §5.1c + tombol **Tarik image** — `docker pull` seluruh image template, §5.20), dan **Branding** (nama + logo dashboard, §5.40). Tab awal dari `?tab=` (whitelist `TABS`), daftar tab dikirim sebagai `$tabs` (view tidak membaca request), dan header menampilkan versi PHP runtime (`$php_version` = `PHP_VERSION` worker). Endpoint: `GET /nginx`, `POST /nginx/reload`, `POST /nginx/templates/pull` & `GET /nginx/templates/pull/status`, `POST /nginx/branding` & `POST /nginx/branding/reset` (admin-only → **404** non-admin, wajib CSRF, selalu PRG ke `/nginx?tab=branding`). **Admin-only → 404 non-admin** (`index()` melempar `AppAccessDenied`; seam `isAdmin()`), dan menu **Config** disembunyikan dari member di UI |
| `BrandingController` | Penyaji **logo brand kustom** `GET /branding/logo` — **publik, path eksak** (`AuthMiddleware::PUBLIC_PATHS`) karena halaman login butuh logo sebelum sesi ada. Tanpa input path/nama dari request: satu-satunya sumber berkas `BrandingLogo::path()`; belum ada logo ⇒ **404**. Respons `Webman\Http\Response` dengan `Content-Type` hasil validasi, `X-Content-Type-Options: nosniff`, `Cache-Control: no-cache`, `ETag` + `If-None-Match` → **304** (termasuk `W/"…"`/daftar/`*`) |
| `DatabaseController` | Halaman `/database`: daftar container DB (difilter kepemilikan app — non-admin tanpa container eksternal) + **reverse proxy Adminer** per container (`/database/{container}/adminer…`, §5.17). **`findOwningApp()` adalah titik otorisasi tunggal** (dipakai daftar & proxy): koneksi Engine, helper, dan kredensial hanya disentuh setelah otorisasi lolos; penolakan `AppAccessDenied` → **404**. Proxy hanya mediator ke `app\library\Adminer\*` (state hanya di sesi; tanpa properti controller) |
| `VolumeController` | Halaman `/volumes`: daftar volume ber-label compose **dari setiap server yang boleh dilihat user** — lokal dari Engine host ini, agent dari `AgentDeployer::backupVolumes()` (`GET /backups/volumes`) **per server** sehingga volume **yatim** server agent ikut terlihat (admin **selalu** menghubungi setiap server agent; `orphaned` diputuskan dari `apps.json` server itu) + bersihkan volume **yatim**; daftar disaring ke app yang boleh diakses, **purge hanya Engine host ini** (baris agent `can_purge=false`; belum ada op/job `volume_rm` di agent). Kolom **Ukuran** (storage terpakai per volume) dimuat asinkron dari `GET /api/volumes/usage` agar render halaman tidak menunggu Engine menelusuri filesystem: volume lokal lewat `VolumeUsage::summarize` atas `GET /system/df` host ini, volume agent lewat `AgentDeployer::volumeUsage()` → `GET /system/volume-usage` **server itu** (peta `servers[serverId]`; hanya nama milik project yang boleh diakses user yang dikirim; Engine lokal gagal ⇒ `engine_error` + `total_human:null` (bukan "0B"), sehingga `/monitor` menampilkan "tidak tersedia") |
| `backup/*` (`app\controller\backup`) | Backup volume ke S3 (§5.15): halaman/status/snapshot, run & restore, arsip, dump DB. 5 controller konkret + `BackupControllerBase` — peta di [§4.1a](#41a-peta-controller-per-domain). |
| `NetworkController` | Halaman `/networks`: daftar network Docker (built-in diberi label & dilindungi, milik app aktif ditandai "dikelola app"), buat shared network (bridge/overlay/macvlan + IPAM + flag attachable/internal), detail network (container terhubung + connect/disconnect), hapus network dengan proteksi berlapis (built-in / dipakai container / milik app aktif ditolak). Operasi global (buat/hapus/connect/disconnect) hanya admin; daftar disaring per app yang boleh diakses |
| `MonitorController` | Halaman global `/monitor` (nav sidebar) + `GET /api/monitor/overview` (metrik host + seluruh container) & `GET /api/monitor/host` (metrik host saja, untuk polling ringan kartu host — tanpa Engine). Read-only, tanpa state, tanpa CSRF. Otorisasi bertingkat: admin melihat semua container di host (termasuk container eksternal), user lain hanya container milik app yang boleh diakses (§5.13). **Multi-server (F3c, §5.30)**: `overview` juga mengembalikan agregat `data.servers[]` (entri lokal + server agent yang boleh dilihat user — non-admin hanya server yang menaungi app terlihat; metrik dibaca **di** server itu); server agent mati ⇒ `status:'offline'` + `error` tersanitasi **tanpa** menggagalkan halaman; `host` tetap server lokal saja |
| `AppMetricsController` | Snapshot metrik **satu app** untuk tab Info detail app (§5.13a, SPECS §8d.1): `GET /api/apps/{id}/metrics[?storage=1]` → `{code:0,data:{at,usage,storage}}`; ability `view` (Viewer+), app tak dikenal/user tanpa hak ⇒ **404** (bukan 403), parameter `storage` berbentuk array/objek ⇒ **400**. `usage` = CPU/RAM container app (`Monitor\AppMetrics::usage()`; `null` bukan 0 bila tak terbaca) + `containers_detail[]`; `storage` = volume project + writable layer container (`Monitor\AppStorage`, image tidak dihitung) dan **hanya** dihitung bila diminta karena `docker system df` mahal. App yatim/server hilang ⇒ tetap **200** dengan `usage.error` generik + `storage.available:false`; pesan galat agent disanitasi `AgentError::sanitizeForServer()`. Tanpa state lintas-request — grafik dirakit browser |
| `UserController` | Kelola user — **khusus admin**: tambah/hapus user, ubah role (admin/member), ganti password, **set/hapus `email`** user (`POST /users/{id}/email`, prasyarat top-up Duitku §5.18), serta **grant pemilihan server** (`POST /users/{id}/servers` → flag `server_select` + allowlist `server_ids[]`; id tak dikenal dibuang, seluruh allowlist invalid ⇒ ditolak, §5.26/SPECS §6.1); halaman `/users` menampilkan saldo kredit read-only (`CreditAccount::allBalances()`) + opsi server aman (`ServerResolver::option()` — hanya `id`/`name`, tanpa token/PEM/`base_url`/`rates`). Menghapus user **mengalihkan app miliknya** ke admin yang menghapus; bila pemilik lama pihak yang ditagih (member) & billing aktif, app hasil transfer yang masih hidup **dihentikan otomatis** (anti-escape billing — `AppStopper::stopTransferredToExemptOwner`, §5.18) |
| `CreditController` | Halaman & aksi kredit (§5.18): `GET /credits` (member = saldo/pemakaian/ledger/top-up **via modal** `#topupModal`; admin = semua user + deposit + penagihan manual), `POST /credits/deposit` & `POST /credits/charge` (**admin-only → 404** non-admin), `POST /credits/email` (**warisan/BC** — UI kini memakai `/profile/email`; hanya email user login — anti IDOR), `POST /credits/topup` + `GET /credits/topup/return` (order id dari `?order=` **atau** `?merchantOrderId=`; order milik user login; kosong/non-skalar → 404; order `pending` ⇒ `TopUpService::reconcile(force: true)`; `resultCode`/`reference` dari browser **tidak dipercaya** — hanya memilih pesan flash dan hanya bila `resultCode` ada), `GET /api/credits/methods` (satu-satunya jalur yang menyentuh jaringan, dipanggil JS saat **modal top-up pertama dibuka** — `shown.bs.modal`, bukan saat load): sebelum menambah `group`, kanal **disaring ulang** `DuitkuClient::isAllowedMethod()` (**defense-in-depth** — kanal di luar allowlist/`HARD_EXCLUDE_METHODS`, mis. `VC`/`OL`, tak bisa tampil walau `paymentMethods()` regresi); tiap item `data` diberi key **`group`** (`PaymentMethodCatalog::decorate()`) dan daftar **diurutkan per grup kanonik** (stabil di dalam grup); payload view `GET /credits` memuat **`methodGroups`** (`[{label,codes:[…]}]`, dari `groupedCodes()`) di samping `methods` lama (kompatibilitas/fallback). Mediator murni: seluruh logika di `app\library\Billing\*`; tanpa state properti lintas-request. Untuk admin, `topupIssues()` (dari `DuitkuClient::configurationIssues()`) menjelaskan **alasan top-up nonaktif** di `/credits`, dan — **non-blocking** — `topupWarnings` (`DuitkuClient::configurationWarnings()`) + `topupCallbackUrl`/`topupReturnUrl` (getter lokal, tanpa jaringan; `[]`/`''` bila seam melempar) memberi diagnostik path callback/tunnel/return; member menerima `[]`/`''` (tidak melihat detail infrastruktur) |
| `ProfileController` | Halaman **Profil** self-service (`GET /profile`, semua user login; view `app/view/profile/index.php`) untuk **diri sendiri**: kartu **Edit profil** (form email → `POST /profile/email`, `maxlength=50`) + kartu **Ubah password** (form → `POST /profile/password`) + kartu **Akun** baca-saja (username, badge peran, saldo). Urutan `changePassword()` (§5.5a): field non-skalar ⇒ flash `Password tidak valid.` → `UserStore::verifyPassword()` dengan id **dari sesi** (`Password saat ini salah.`) → konfirmasi identik (`Konfirmasi password baru tidak cocok.`) → `UserStore::changePassword()` (minimal 6 karakter) → flash `Password diperbarui.` + `redirect('/profile')`. **Anti-IDOR**: `id`/`user_id`/`username` dari request diabaikan mutlak — id selalu dari `current_user()`. Mediator murni: validasi email (≤50 karakter + `FILTER_VALIDATE_EMAIL`) **tidak diduplikasi** — didelegasikan penuh ke `UserStore::setEmail()`; email kosong = hapus; input non-skalar (`email[]=…`) → flash + redirect `/profile` (**bukan** 500); sukses/gagal selalu redirect `/profile`. Seam pengujian `UserStore` berpath temp; tanpa state properti lintas-request. Kartu **Verifikasi dua langkah (2FA)** (SPECS §6.4, §5.5b): aksi `startTotpSetup()` (`POST /profile/2fa/setup`), `enableTotp()` (`POST /profile/2fa/enable`), `disableTotp()` (`POST /profile/2fa/disable`), `regenerateTotpRecovery()` (`POST /profile/2fa/recovery`) — mediator tipis ke `TwoFactorService`/`UserStore`; id target **selalu** dari `current_user()`, secret setup hanya di session `2fa_setup`, kode pemulihan plaintext sekali tampil via `2fa_recovery_once` |
| `PaymentController` | Callback pembayaran Duitku **publik** (`POST /payments/duitku/callback`, §5.18): verifikasi `TopUpService::handleCallback()` (merchantCode + signature HMAC `hash_equals` + kecocokan amount + idempotensi) lalu memetakan hasil ke status HTTP (404 fitur/kredensial mati; 400 payload cacat; 403 verifikasi gagal; 200 `OK` tentatif agar Duitku tidak retry). Tanpa session, tanpa data sensitif di respons; audit ringkas ke `runtime/logs/billing/` |
| `DomainController` | **Satu halaman `/domains`** untuk domain + SSL (dua tab: **Semua Domain** = tabel app + parkir, **Domain Parkir** = CRUD) — SPECS §8j, §5.38. Mediator tipis: `GET /domains` & `GET /api/domains/status` terbuka **semua user login** (baris app `AppAccess::visible()` + `can_ssl` per baris; baris parkir hanya admin), sedangkan CRUD parkir + aktivasi SSL parkir **admin-only → 404** non-admin (dievaluasi sebelum store). `GET /ssl` ⇒ `legacySsl()` **302 `/domains`**. Payload `domain/index`: `rows`, `domains`, `isAdmin`, `tab`, `active`, `maxHtmlBytes`, `appDomain`, `errors`, `sslSupported`, `filter`, `filterActive` (filter `?domain=` diterapkan **setelah** otorisasi, lihat `DomainFilter`); baris `rows` memuat `ssl_queue_position`/`ssl_queue_size` untuk state `pending` (dekorasi `SslQueue::decorate()` dijalankan **di dalam** `SslDomainRows::appRows()`/`parkedRows()`, fail-safe, §5.44); `domain/form`: `domain`, `input`, `errors`, `isEdit`, `active`, `maxHtmlBytes`, `appDomain`, `wwwSuggestion`, `ssl` (`status/message/error/expires_at/can_ssl/form_url/ajax_url`). Seam `store()`/`content()`/`manager()`/`parkedSslEnabler()`/`renderView()`; **tanpa state properti** lintas-request |
| `SslController` | Jalur SSL **app** yang tetap dipakai halaman `/domains`: `enable()` (`POST /ssl/{id}/enable`, 302 → `/domains` + flash) & `apiEnable()` (`POST /api/ssl/{id}/enable`) berbagi satu inti `enableDomain()`; `apiStatus()` (`GET /api/ssl/status`) = **alias kompatibel** baris app saja. `enableDomain()` **tidak** men-spawn worker: status slot `pending` + `*_stage='queued'` ditulis lebih dulu lalu `SslQueue::enqueueApp()` (antrean global §5.44, dedupe per app+domain+slot); pesan sukses memuat "posisi N dari M", `apiStatus()` meneruskan `ssl_queue_position`/`ssl_queue_size`. Baris dirakit `SslDomainRows::appRows()` (satu sumber dengan `/domains`); `GET /ssl` sendiri kini ditangani `DomainController::legacySsl()` (302) |
| `IndexController` | Halaman utama dashboard (`view('index/hello')`) |
| `HealthController` | `GET /healthz` (**publik**, §5.14): status + SHA/branch dari `.git` (tanpa proses git) — dipakai helper self-update untuk memutuskan sehat/rollback, dan bisa dipakai monitoring eksternal |
| `UpdateController` | Endpoint self-update dashboard (§5.14): `GET /api/update/status` (semua user login), `POST /api/update/check`, `POST /api/update/start`, `POST /api/update/rollback` (admin). Panel-nya di halaman `/nginx` |
| `ErrorController` | **Error Log "Rekam Error"** (SPECS §7.18, alur §5.43): halaman `/errors` (filter status/kind/app/q + pagination) & `/errors/{id}` (sampel event), API baca `GET /api/errors`, laporan klien `POST /api/errors`, aksi ubah status/hapus ber-CSRF. **Admin-only → 404** non-admin (dievaluasi sebelum menyentuh store); payload divalidasi `ErrorInput`, disimpan lewat `ErrorReporter`/`ErrorStore`; mediator tanpa state properti, stack/context dari klien selalu dirender `e()` |
| `ServerController` | Halaman & aksi **registry server** (multi-server F0, §5.26, SPECS §7.14) — admin-only → **404** non-admin (`guard()` → `ServerAccess::requireManageServers()`): `GET /servers` (daftar), `GET /servers/create` + `POST /servers` (Add Server: name/kind/base_url/token/PEM/domain/port_range/notes), `GET/POST /servers/{id}` (edit; baris lokal hanya `domain`/`notes`/`rates` via `ServerResolver::validateLocal()`; form mengirim `rate_cpu`/`rate_ram`/`rate_backup` ⇒ `rates`, semua kosong = hapus override), `POST /servers/{id}/delete`, `POST /servers/{id}/test` (**Test connection**: panggil agent `GET /healthz`/`/version` dengan pinning → simpan `status`/`agent_version`/`capabilities`/`last_seen_at`), `POST /servers/{id}/agent-update` (admin-only; `AgentVersionGate::check()` **dulu** ⇒ 400 tanpa job, lalu job tingkat server `self_update` di agen; balasan hanya `job_id`), `GET /servers/{id}/agent-update/status?job&offset` (**dashboard-only**; non-admin ⇒ 404; `agentUpdateStatus()` meneruskan rekaman job + potongan log agen lewat `AgentDeployer::serverJobProgress()`; galat **transien** ⇒ **200 `unreachable`** + `reason`, galat **deterministik** ⇒ 400 + `reason` — §5.33a), `GET /api/servers` (daftar untuk JS, **tanpa** token/PEM). Token & PEM tidak pernah dirender ulang (`publicServer()`/`formServer()` membuang/mengosongkannya) |
| `server/ProvisionController` | **Provisioning server agent via Ansible** (opsi B, §5.21b, SPECS §8k) — admin-only → **404** non-admin: `GET /servers/provision` (form, payload `agent_key` = status kunci bersama: `exists/slot/public_key/fingerprint/public_path`), `POST /servers/provision/keypair` (buat/baca kunci provisioning bersama `rames-agent-key`; respons `{code:0,public_key,fingerprint,created}`, idempoten, **tanpa** private key), `POST /servers/provision` (validasi `ProvisionInput` → job `provision_jobs` skema v6 → tolak **422** bila kunci bersama belum dibuat → spawn `cli/provision.php` lewat `DetachedWorker`; balasan `{code:0,job_id,status_url}`; form **tidak lagi** meminta `private_key`), `POST /servers/provision/jobs/delete` (hapus job terminal + log: `job=<id>` atau `scope=failed|done|finished`; job aktif ⇒ 409), `GET /servers/provision/jobs` (daftar job terbaru untuk panel pemantau di `/servers` & tabel job di halaman provision: `{code:0,jobs:[…]}` + `can_cancel` turunan status; **tanpa** rahasia), `GET /servers/provision/status?job&offset` (status + potongan log, **tanpa** token/PEM), `POST /servers/provision/cancel` (`AnsibleRunner::cancel()` + status `cancelled`). Route didaftarkan **sebelum** `/servers/{id}` dan tidak ada di mode agent |
| `AgentController` | Route mesin agent (mode `RAMES_MODE=agent`, §5.21): `GET /healthz` (`{ok, service, mode:'agent', version}`, dipakai **Test connection** + monitoring) & `GET /version` (`{agent_version, capabilities, min_control_plane_version}`; `capabilities` = op yang benar-benar didukung = `DeployWorkerLauncher::MODES`). Keduanya **butuh token** (tidak ada route publik di agent) |
| `AgentJobController` | Route job & proyeksi app di agent (§5.23): `POST /jobs` (validasi op terhadap `DeployWorkerLauncher::MODES` — termasuk op F2 `nginx_write`/`nginx_remove`/`nginx_reload`/`ssl_issue`/`ssl_revoke` + payload app → upsert proyeksi `AgentAppProjection` → materialisasi artefak `AgentArtifactMaterializer` → spawn worker detached; balas `{job_id, op, log_offset}`; **PID worker disimpan di rekaman job** untuk pembatalan), `GET /jobs/{id}` (status), `GET /jobs/{id}/log?offset=N` (potongan log deploy app ≤256 KiB + header `X-Rames-Offset`; pembaca diarahkan ke `DeployWorkerLauncher::logDir()`), **`POST /jobs/{id}/cancel`** (hentikan worker + grup build lewat `DeployCanceller`, status proyeksi ikut dipulihkan; job `done`/`error` ⇒ 409), `GET /apps/{id}` (state eksekusi untuk pull, whitelist `APP_FIELDS` — tanpa `env`/deploy key), `GET /apps/{id}/nginx` (perakitan config Nginx vhost dilakukan **di agent**), `GET /apps/{id}/services` (nama service + batas CPU/memori base compose server itu; read-only, app tak dikenal ⇒ 404, compose tak terbaca ⇒ 200 + `error`, §5.12a), `POST /nginx/check` (preflight `ensureWritable()` app-less, bukan job), `POST /apps/check` (preflight **ketersediaan direktori app** sebelum create — read-only, bukan job, §5.22). Semua lewat middleware token |
| `AgentLogController` | Log container app **di server agent** (F3a multi-server, §5.28): `GET /apps/{id}/logs?container=&tail=&timestamps=` membaca Engine server itu (`DockerClient` agent) dan mengembalikan teks yang sama bentuknya dengan `LogController` lokal. Container divalidasi `AgentDeployer::containerRef()` (bentuk nama + keanggotaan data proyeksi). **Tanpa state** & **tanpa audit** (identitas user hanya ada di control plane) |
| `AgentTerminalController` | Sesi terminal app **di server agent** (F3a multi-server, §5.28): `POST /terminal/open` (`DockerExec::open()` di host itu), `GET /terminal/{token}/stream` (SSE chunked), `POST /terminal/{token}/input`, `POST /terminal/{token}/close`. Tiap panggilan membawa `app_id` (query/body) sehingga validasi "token milik app ini" tetap satu sumber di `DockerExec::sessionInfo($token, $appId)`. **Sesi TIDAK ditutup saat klien drop** — hanya `close`, proses keluar, atau prune TTL. Audit **tidak** ditulis di agent |
| `AgentFilesController` | File manager **di server agent** (F3b multi-server, §5.29): `GET /files/list\|read\|download` + `POST /files/write\|mkdir\|rename\|delete\|move\|upload\|extract`. Memakai library yang sama dengan jalur lokal (`ContainerFiles`/`PathGuard`/`FilesInput`/`TextContent`/`ArchiveGuard`) sehingga batas 2 MiB editor, 5000 entri listing, tolak biner, dan **zip-slip** tetap berlaku; sumber app = proyeksi agent (`app_id` di query/body), container divalidasi (`AppContainers::resolve`) & wajib berjalan (409). Envelope galat domain HTTP **200** (`{code:<status>,msg}`) **kecuali** `/files/download` yang memakai HTTP nyata (409/413/404) supaya control plane membedakan JSON galat dari isi berkas. Batas transfer `AgentDeployer::MAX_TRANSFER_BYTES`; berkas temp selalu dibersihkan. **Tanpa** otorisasi user (ditangani control plane); audit tidak ditulis di agent |
| `AgentDockerController` | Monitoring **di server agent** (F3c multi-server, §5.30): `GET /system/host-usage` (`/proc` + `statvfs`/`DISK_PATH` server ini via `ResourceCollector::hostSnapshot()`) & `GET /monitor/containers` (statistik container Engine server ini via `ResourceCollector::collect()`, `DockerClient` server ini). Selalu metrik **server ini** — `/proc`/Engine/storage host control plane tidak pernah dipakai. Tanpa otorisasi/penyaringan (tanggung jawab `MonitorController`); kegagalan Engine ⇒ `error` terisi, bukan respons gagal. Juga `GET /system/disk-usage?project=<app>` (§5.13a/§5.30): ukuran storage **server ini** untuk satu compose project (volume project + writable layer container; image tidak dihitung) via `AppStorage::summarize()` atas `DockerClient::getDiskUsage(['volume','container'])`; `project` wajib cocok `^[a-z0-9][a-z0-9-]*$` dan ≤63 karakter (nilai tidak sah/berbentuk array ⇒ **400** tanpa digemakan), kegagalan Engine ⇒ **502** (pola `hostUsage()`), muatan mentah Engine (`Labels`/`Id`/`SizeRootFs`) tidak ikut — pesan galat agent baru disanitasi di control plane (`AgentError::sanitizeForServer()`). Juga `GET /system/volume-usage`: ukuran tiap volume ber-label compose **server ini** (`VolumeUsage::composeRows` atas `GET /system/df`, `{name, project, size, ref_count, size_human}`; volume ber-label `rames.role=dashboard-db|agent-db` dikecualikan), dipakai kolom Ukuran `/volumes` untuk baris server agent; kegagalan Engine ⇒ **502** |
| `AgentAdminerController` | Database/Adminer **di server agent** (F3d multi-server, §5.31): `GET /database/containers` (deteksi container DB Engine server ini via `DbContainerDetector`) & proxy `ANY /adminer/{container}[/{path:.*}]`. Body permintaan diteruskan **mentah** (multipart/unduhan utuh — HTML Adminer tidak pernah disunting), `X-Forwarded-Prefix` dari control plane dipakai helper untuk merakit URL, dan **jar cookie** dititipkan control plane lewat header `X-Rames-Adminer-Jar` (base64 JSON, tidak pernah ke browser). Otorisasi & kepemilikan container tetap diputuskan control plane; agent hanya memvalidasi bentuk nama & memastikan container itu container DB server ini |
| `AgentNetworkController` | Network & volume **di server agent** (F3d, §5.31): `GET /networks`, `GET /networks/{id}`, `GET /volumes`, `POST /networks/create\|{id}/connect\|{id}/disconnect\|{id}/delete` — semuanya memakai Engine server ini. Penolakan **sambungan lintas server** ada di control plane (`NetworkController::assertContainerServer()`): shared network hanya bermakna dalam satu server |


### 4.1a Peta controller per domain

Sejak refactor struktural, controller **tidak lagi** berupa satu kelas raksasa. Konvensi yang berlaku:

- **Satu domain fitur = satu direktori namespace**: `app/controller/<domain>/`, namespace `app\controller\<domain>`.
- Controller konkret **hanya mediator**: tanpa state properti, tanpa logika bisnis (logika tetap di `app/library/`, §4.3), otorisasi lewat satu pintu `AppAccess` (`AppControllerBase::findApp()`).
- **Helper lintas-controller hanya di base abstract** (`AppControllerBase`, `AppArtifactControllerBase`, `BackupControllerBase`); helper yang hanya dipakai satu controller tetap di controller itu.
- **Kontrak URL tidak berubah**: pemecahan controller hanya memindahkan handler ke kelas baru — path/verb/urutan route lama dipertahankan. Baseline yang diuji `tests/AgentModeTest.php` saat ini **159 definisi route dashboard / 165 pasangan method+path**; fitur baru menambah route (mis. `POST /apps/{id}/ports`, `POST /servers/provision/keypair`) tanpa mengubah kontrak yang sudah ada.
- Test yang perlu memanggil helper/protected controller memakai `tests/Support/AppControllerLocator.php` (refleksi nama method → kelas pemilik + instance konkret). Ini **helper test**, bukan bagian arsitektur produksi.

### Impor project compose eksternal (`ListController`, admin-only)

- `ListController::importForm()` (`GET /apps/import`) & `importStore()` (`POST /apps/import`) — **admin global saja**; non-admin melempar `AppAccessDenied` (**404**, bukan 403). Render halaman menjalankan `ComposeDiscovery` (read-only); kegagalan Engine dikirim sebagai `engineError` dan halaman tetap 200. `importStore()` hanya mediator — seluruh keputusan (discovery ulang, validasi `primary`, keunikan nama, bentuk record) ada di `ComposeImporter::import()`; **tidak ada deploy/worker** yang di-spawn.
- **Guard mutasi app impor**: `ImportedApp::assertManageable()` dipanggil di action rebuild/rollback/apply compose, simpan/import/upload env, network eksternal, prefix nama container, dan batas resource (paralel dengan `LocalDeployer::deploy/rebuild/rollback/apply/applyEnv/applyLimits/teardown`). Penolakan = flash error berisi pesan tindakan, bukan eksekusi compose.
- **Cabang delete** (`DeploymentController::delete()`): memeriksa `ImportedApp::isImported()` lebih dulu — app impor hanya **melepas record**: `removeNginxConfig()` (bila server app diketahui) + `EnvManager::remove()` + `AppStore::delete()`; tanpa `teardown()`, tanpa `cleanupDir`, tanpa volume.
- **Konteks detail** (`InfoController::detail()`): mengirim `ImportedApp::context()` (`imported`, `compose_dir`, `compose_paths`, `imported_at`) dan memakai `importedLimitsContext()` (`canManage=false`) — daftar service tetap dari container nyata karena tidak ada base compose lokal.
