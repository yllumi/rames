# 7. Keamanan (Phase 1)

> Bagian dari [dokumentasi arsitektur](../ARCHITECTURE.md) · Spesifikasi: [SPECS.md](../SPECS.md) · Panduan operasional: [DETAILS.md](../../DETAILS.md)

- Password bcrypt; tidak pernah plaintext / di-log.
- CSRF token untuk semua mutasi.
- **Ownership & role**: setiap app punya `owner_id` + `members`; semua akses diperiksa lewat `AppAccess` (satu pintu) di **setiap** endpoint — termasuk terminal, database manager, SSL, volume, dan network. Akses tidak sah → **404** (bukan 403) supaya keberadaan app user lain tidak bocor. Tombol di UI hanya lapisan kedua (server tetap menolak).
- **Kelola user khusus admin**; admin terakhir tidak bisa dihapus/diturunkan; menghapus user mengalihkan app miliknya ke admin.
- **Ubah password self-service (§5.5a)**: `POST /profile/password` hanya mengubah user login (id dari sesi; `id`/`user_id`/`username` request diabaikan), wajib password saat ini yang benar (`UserStore::verifyPassword`, `password_verify`) + konfirmasi identik; minimal 6 karakter ditegakkan store; password tidak di-trim/tidak dicatat. Route tetap di bawah `AuthMiddleware` + `CsrfMiddleware` (tidak exempt) — dikunci `tests/ProfilePasswordRouteGuardTest.php`.
- Operasi global (network, reload Nginx, purge volume) hanya admin.
- **Domain parking & SSL** (§5.38, SPECS §8j): `GET /domains` + `GET /api/domains/status` boleh dibaca **semua user login** — server menyaring baris app (`AppAccess::visible()`), **tidak** mengirim baris parkir untuk non-admin, dan membuang objek `app` dari payload (tanpa bocoran dokumen app). Seluruh aksi pengelolaan parkir + aktivasi SSL parkir **admin-only** — non-admin ⇒ **404** (`DomainController::guard()`/`apiEnableParked()`, dievaluasi **sebelum** membaca store/memanggil manager), dan tab/tombol hanya dirender untuk admin (lapisan kedua, bukan pengaman). Semua mutasi (termasuk `/domains/parked/{id}/ssl` & `/api/domains/parked/{id}/enable`) tetap lewat `CsrfMiddleware` — `_token` wajib. **Anti-injeksi direktif Nginx**: nilai yang masuk config divalidasi ulang saat render (`ParkedNginxConfig::render()` → `ParkedDomainValidator`) — domain = FQDN label DNS ketat (tanpa wildcard/underscore/spasi/`..`), target redirect menolak userinfo/query/fragment/spasi/kontrol & karakter quoting (`"'\\<>{}$;`\|^`), path `root` wajib absolut & bebas spasi/kutip/`;`/`{}`/`#`/`$`. **Path traversal**: id entri wajib `/^pd_[a-f0-9]{12}\z/` dan diperiksa **sebelum** operasi filesystem (id berisi `../` tidak bisa keluar dari `PARKED_ROOT`); root relatif/ber-`..` ditolak. **HTML tepercaya admin**: isi mode `html` adalah konten mentah yang disajikan sebagai berkas statis ke publik — form/CRUD parkir tidak boleh dibuka untuk role lain, dan jangan pernah menambahkan sanitasi/escape yang membuatnya tampak "aman untuk member". **Fallback cert hilang**: status `active` tanpa berkas cert ⇒ config parkir HTTP-only agar `nginx -t` seluruh host tidak gagal (GOTCHA no. 47).
- **Multi-server — penyaringan daftar server di SISI SERVER (§5.30)**: `GET /api/monitor/overview` menyaring `data.servers[]` dengan `ServerAccess::visibleServers()` — non-admin hanya menerima server yang menaungi app yang boleh ia lihat, dan server lain **tidak pernah dihubungi** (entrinya tidak dirakit). Penyaringan di `public/js/monitor.js` hanya lapisan kedua; jangan pernah mengandalkannya sebagai pengaman.
- **Multi-server — `?server=` non-lokal yang tidak berhak = 404 fail-closed (§5.31)**: pemilih server (`/networks` + aksi mutasinya) menolak server di luar jangkauan user lewat `AppAccessDenied` (**404**, bukan 403 dan bukan fallback ke server lokal) **sebelum** efek samping apa pun (`NetworkController::assertServerVisible()`); server lokal tidak pernah disubstitusi. Nuansa yang disengaja: id tak dikenal ⇒ halaman kosong + pesan `Server tidak dikenal` (bukan 404), sedangkan server **ada** tetapi bukan milik user ⇒ 404 — perilaku ini pra-ada sejak F3c.
- **Multi-server — op data (backup/restore/dump) dieksekusi di server pemilik volume (§5.32)**: kredensial restic/S3/passphrase **tidak pernah** masuk payload job, rekaman job, log, atau `argv`; agent memakai env/berkas kredensialnya sendiri (0600). Op yang belum didukung di agent (**unduh snapshot/`.sql` dari arsip** — `GET /api/backups/archive/snapshots` & `GET /backups/archive/sql` untuk `server_id` non-lokal) ditolak **422 fail-fast**; `restore_archived` **didukung** sebagai job tingkat server di server itu — bukan dijalankan di control plane dengan repo/volume yang salah.
- **Multi-server — `capabilities` diutamakan atas string versi (§5.33)**: keputusan op yang boleh dikirim control plane dibaca dari **capabilities** hasil Test connection (`AgentJobController::OPS` = `DeployWorkerLauncher::MODES` = daftar mode `cli/deploy.php` — satu sumber, tak ada op "senyap"); string versi hanya dipakai sebagai gerbang *minimum* (`MIN_AGENT_VERSION`/`MIN_CONTROL_PLANE_VERSION`). Capabilities **kosong** = "belum diuji" ⇒ tidak ditolak di control plane (hanya peringatan) karena keputusan akhir tetap di agen (op tak dikenal ⇒ 501) — menolak berdasarkan data yang tidak ada akan memblokir instalasi baru tanpa alasan.
- **Multi-server — satu clock penjadwalan di control plane (§5.34)**: hanya dashboard yang punya timer (`host/systemd/volume-backup.timer` → `cli/backup.php run`); `agent/install.sh` **tidak** memasang timer apa pun. Run terjadwal tanpa `serverId` memfans-out volume bertanda `scheduled` milik server agent sebagai job ke server pemiliknya, sehingga jadwal & hasil hanya punya satu tempat melihat (control plane) — agent tetap bisa menjalankan backup manual lewat job kapan saja. Konsekuensi yang harus dijaga: exit code & laporan mengikuti hasil **per volume/server**, bukan status satu host (§5.34).
- **Multi-server — op tingkat server memakai slot target, bukan app (§5.34)**: `template_pull` (slug), `self_update` (`agent`), `restore_archived` (nama volume arsip) memakai `argv[1]` sebagai *target* dan berjalan **sebelum** pemuatan app di store — op ini tidak boleh dibuat menuntut proyeksi app (`app.id`) karena volume arsip/template/agen memang tidak punya app di server itu.
- **Batas resource** (§5.12a): ability `limits` = **admin saja** (satu pintu `AppAccess`); owner/operator/viewer hanya melihat nilai read-only. Nama service dari POST tidak dipercaya (whitelist dari base compose), nilai divalidasi ketat, dan base compose yang tidak konsisten antar keluarga field ditolak **sebelum** menulis file. `--compatibility` dilarang untuk fitur ini. **App server agent**: whitelist service berasal dari base compose **agent** (`GET /apps/{id}/services` — read-only, hanya nama service + angka `cpus`/`memory_mb`, tanpa secret/token/host), control plane **tidak pernah** menulis artefak app agent (metadata saja lewat `ResourceLimits::persistMetadata()`, penerapan = job `apply_limits`), dan agent lama tanpa endpoint (404) dipetakan ke pesan "perbarui agent" — bukan galat server atau fallback ke host lokal.
- **Monitoring** (`/monitor`): daftar container disaring di sisi server — non-admin hanya menerima container app yang boleh diakses, container eksternal (dan angka host yang rinci) hanya untuk admin; endpoint read-only (GET) sehingga tidak butuh CSRF dan tidak mengubah apa pun.
- **Metrik per-app** (`GET /api/apps/{id}/metrics[?storage=1]`, §5.13a): ability **`view`** (Viewer+) — app tak dikenal / user tanpa hak ⇒ **404** (bukan 403) dan Engine tidak disentuh. Parameter `storage` berbentuk array/objek ditolak **400** tanpa menggemakan nilainya. Respons tidak memuat IP/secret/host internal: galat jalur agent disanitasi `AgentError::sanitizeForServer()` (token, `base_url`, PEM dibuang) sebelum dikirim; jalur lokal boleh memuat pesan Engine (paritas `/monitor`). Jalur agent hanya mengirim **nama compose project app itu** ke `GET /system/disk-usage` (pola `^[a-z0-9][a-z0-9-]*$`, ≤63 karakter — nilai lain 400 **sebelum** Engine dipanggil) sehingga tidak ada cara meminta ukuran project/server lain; endpoint agent tanpa otorisasi user karena control plane sudah menyaring akses.
- **Backup DB dashboard** (§5.19): seluruh route `POST /backups/db/run|prune|restore` & `GET /backups/db/download` **admin-only** (non-admin → **404**, satu pintu `BackupController::isAdmin()`). `restore()` defensif — validasi nama (basename) + `realpath` prefix (tolak traversal **sebelum** menyentuh berkas), `PRAGMA integrity_check`, tabel inti wajib ada, dan safety snapshot `pre-restore-*` dibuat **sebelum** mengganti berkas; penggantian atomik (copy→rename) + `SqliteDatabase::reset()`. Snapshot & berkas DB berada di named volume `rames` (bukan di repo), gitignored (`database/*.sqlite*` bila `RAMES_DB_DIR` diarahkan ke repo). Backup/restore diserialkan mutex `flock` (non-blocking).
- **Backup volume** (§5.15): ability `backup` = operator, `restore` = owner (destruktif); satu pintu `BackupAccess`→`AppAccess`, penolakan **404**, volume yatim hanya admin. `POST /backups/refresh` **hanya** admin global (non-admin → 404); `POST /backups/schedule` dijaga ability `backup` (owner/operator app pemilik volume; viewer/stranger → 404, volume yatim admin-only) plus gerbang kredit **saat menyalakan** (402); respons status disanitasi `publicStatus()` (daftar-putih — `volumes`/`error` mentah **dibuang**) dan baris volume disaring `BackupAccess::visible()` sehingga **cache bersama tidak bocor lintas-app**. Kredensial S3 hanya lewat env-file 0600 (`--env-file`) & passphrase restic lewat `--password-file` (`:ro`) — tidak pernah di argv/`ps`, log, atau JSON; nama volume & id snapshot divalidasi regex sebelum masuk argv helper; semua spawn array + `bypass_shell` + `SigchldGuard`. Snapshot filesystem **hanya** sah saat container berhenti (`VolumeStateGuard`), tanpa jalur paksa dari UI. Endpoint **arsip** (`archive/snapshots`, `archive/restore`, `archive/sql`) & `data.archived` **admin-only** (non-admin → 404 / `[]`); restore arsip membuat volume **baru** ber-label project (volume lama tidak disentuh) dan unduhan `.sql` memakai nama aman (`safeDownloadName()`) + `X-Content-Type-Options: nosniff` dengan direktori temp dibersihkan `finally`.
- **Database / Adminer** (§5.17): ability `database` = operator (satu pintu `AppAccess`, penolakan **404**); nama container dari request tidak dipercaya (`AppContainers::resolve`) dan koneksi Engine/kredensial hanya disentuh **setelah** otorisasi. Helper Adminer **tanpa port publik**, hanya di network **internal** `rames-helpers` (`internal: true`) dan dijangkau lewat nama container; kredensial DB **tidak pernah** ke argv helper maupun ke browser — jar cookie Adminer hidup di sesi server, `Set-Cookie` Adminer dibuang, cookie sesi Rames tidak diteruskan ke helper. Pengecualian CSRF dibatasi **path-presisi** `#^/database/[^/]+/adminer(/|$)#` (dicek sebelum `post()` agar multipart utuh) dengan kompensasi `AuthMiddleware` global + otorisasi controller + cookie `SameSite=lax` (ditegakkan `config/session.php`; `'secure' => false` — belum dipaksa HTTPS). Attach helper ke network app dibatasi umur `ADMINER_NETWORK_TTL` (prune oportunistik) — **risiko sisa**: selama menempel, helper punya egress & halaman login Adminer (tanpa auth) terlihat container lain di network itu (mitigasi & pemilik di §5.17). Berkas temp respons `runtime/adminer-proxy/` ber-`0700`/`0600`; header `X-Forwarded-*` dari klien dibuang & dibentuk ulang dari konteks dashboard. Batas: timeout proxy **≤ 30 detik** & ukuran respons (default 64 MiB) — dump/import besar diarahkan ke Volume/backup atau Terminal.
- Input divalidasi ketat (slug `[a-z0-9-]`, URL http/https, branch, port int 1–65535).
- **File manager container** (§5.16): ability `files` = operator (satu pintu `AppAccess`, penolakan **404** — operator sudah memegang shell penuh di container yang sama sehingga tidak menambah kuasa). Nama container dari request tidak dipercaya (`AppContainers::resolve`); path wajib absolut & dinormalisasi `PathGuard` dan nama entri tidak boleh memuat `/` atau diawali `-` sebelum masuk `docker exec`/`docker cp`; argumen `docker exec` di-`escapeshellarg` (array + `sh -c` di dalam container), perintah host array + `bypass_shell`; ekstraksi arsip di **host** dengan proteksi zip-slip/symlink keluar (`ArchiveGuard`); byte via berkas temp `runtime/files-transfer/` yang dibersihkan `Workerman\Timer`/`prune()` (bukan ke memori PHP); operasi hanya ke container **berjalan** (berhenti → **409**), tanpa container sementara/volume langsung. Berkas biner → **415**, teks > 2 MiB → **413**. **Semua `docker exec` dijalankan sebagai root** (`-u 0`) agar tidak `permission denied`; konsekuensinya operator+ dapat memodifikasi berkas/bind mount root host lewat UI — batasnya ability `files` (operator+) + audit `runtime/logs/files/{date}.log` (jangan turunkan ke viewer).
- **Template** (§5.1c): definisi template hanya dari folder repo `templates/` (bukan input user/unggahan), nama file pendukung divalidasi relatif & aman, file override generated ditolak, dan nilai rahasia dari template (auto-generate) hanya tersimpan di `database/env/{name}.env` (chmod 0600, gitignored) — tidak pernah masuk repo atau `apps.json` versi kode. Env hasil deploy tetap dipersist di `apps.json.env` seperti env yang diisi user lewat tab Environment.
- Eksekusi command tanpa shell (lihat §6).
- **Self-update** (§5.14): hanya **admin** yang bisa menjalankan update/rollback (cek pembaruan boleh semua user login); update ditolak selama repo punya perubahan belum di-commit (agar pekerjaan lokal tidak tertimpa); helper berjalan sebagai pemilik repo (bukan root) dengan akses socket Docker via `--group-add`; nilai dari plan (SHA/branch/path) divalidasi & diteruskan sebagai argv terpisah (tanpa shell). `GET /healthz` **publik** tetapi hanya mengembalikan `{ok, service, sha, branch, time}` — SHA repo dashboard (repositori publik pada instalasi default) tanpa data instalasi.
- Deploy key SSH per app: private key di `database/keys/` (chmod 0600, gitignored), hanya public key yang ditampilkan; `GIT_SSH_COMMAND` memakai `IdentitiesOnly=yes`, `StrictHostKeyChecking=accept-new`, dan `UserKnownHostsFile` milik sistem.
- SSL: sertifikat Let's Encrypt hanya diaktifkan untuk domain publik (`SslIssuer::isPublicDomain`); `/etc/letsencrypt` di-mount baca-tulis ke container; `CLOUDFLARE_CREDS` (API token) via file dengan izin ketat, bukan hard-coded. **Antrean aktivasi (§5.44)**: permintaan SSL app tetap di bawah ability `ssl` (operator+, penolakan **404**) dan parkir **admin-only**; `SslQueue` hanya menyimpan `domain`/`slot`/id target/`actor_id` — tidak ada kredensial; dedupe `uniq_ssl_jobs_active` mencegah penumpukan job, dan worker hanya menjalankan skrip CLI yang sudah ada (tidak ada perintah dari request).
- `docker.sock` di-mount adalah risiko yang disengaja; semua akses dashboard di balik autentikasi.
- Direktori Nginx host yang di-mount dibatasi hanya `sites-available/` + `sites-enabled/`.
- **Rute proxy tambahan** (§5.6a): disimpan terstruktur (bukan snippet mentah) & divalidasi ketat `NginxRoutes` (maks 20, path absolut, `/.well-known` dicadangkan, tolak `..`/userinfo/query), ability `routes` = operator (satu pintu `AppAccess`, tolak **404**). Penyimpanan transaksional lewat `NginxConfigGuard` (uji `nginx -t` + rollback) agar config invalid tidak pernah tertinggal — config rusak memblokir reload nginx **seluruh** host. `applyRoutes()` tidak melempar: kegagalan rollback dilaporkan lewat `error` (dengan `PERINGATAN` bila pemulihan gagal sebagian), jadi UI **wajib** menampilkan `error` dan tidak boleh menganggap `rolled_back=true` berarti disk sudah bersih. Guard **belum** mencakup `setDomain`/`removeDomain`/`cli/ssl.php` yang masih `applyNginxConfig()` langsung (SPECS §8.2a G3). **Catatan**: jalur subdomain (§5.6b) **sudah** lewat `NginxConfigGuard::applySubdomain()` (transaksional + rollback), bukan jalur `applyNginxConfig()` langsung.
- **Subdomain app** (§5.6b): ability `domain` = operator (satu pintu `AppAccess`, tolak **404**); label divalidasi `app_subdomain_valid()` + keunikan atas FQDN efektif semua app & bentrok `custom_domain` **sebelum** menyimpan; perubahan disimpan transaksional lewat `NginxConfigGuard::applySubdomain()` (uji `nginx -t` + rollback state/config) agar config invalid tidak tertinggal; status SSL subdomain di-reset karena sertifikat terikat nama domain lama (berkas cert tidak dihapus).
- **Callback pembayaran Duitku** (§5.18): pengecualian CSRF **kedua & sempit** `#^/payments/duitku/callback$#` (hanya **POST**, path eksak — pengecualian Adminer tidak dilebarkan) + path publik eksak `AuthMiddleware::PUBLIC_PATHS`. Pertahanan: HMAC-SHA256 `hash_equals` + kecocokan amount + idempotensi + tanpa session. Respons polos tanpa data sensitif (200 `OK`; 400/403/404 tanpa detail). Fitur/kredensial mati ⇒ **404**.
- **Higienitas kredensial billing** (§5.18): `BILLING_DUITKU_API_KEY` hanya lewat `.env`/`config()`; `DuitkuClient::sanitize()` mengganti kemunculannya dengan `[redacted]`, dan `DuitkuCredentialHygieneTest` menjaga agar tidak bocor ke log/pesan/view/JSON.
- **Anti-escape pengalihan kepemilikan** (§5.18): app berjalan yang dipindah dari pemilik ditagih (member) ke pemilik bebas tagihan (admin) **dihentikan otomatis** — berlaku pada pengalihan manual (`AppStopper::stopForBillingEscape`) **dan** hapus user (`UserController::delete()` → `stopTransferredToExemptOwner`), `message`=`REASON_TRANSFER` — agar tidak ada pemakaian gratis tanpa akrual; `billingPayerFor()` defensif `catch (\Throwable)` ⇒ jatuh ke aktor bila `auth.json` tak terbaca (N7; `AuthMiddleware` tetap penjaga utama).
- **Gerbang kredit bukan otorisasi** (§5.18): `BillingGate` menilai **satu user per panggilan** (`assertCanStart`/`assertCanCreate`); **orkestrasi dua subjek** (**aktor lalu pembayar/owner**) berada di `AppController::billingAssertCanStart()` **dan** di worker `cli/deploy.php` — dengan pengecualian exempt (aktor admin **atau** app milik admin) dikecualikan lebih dulu, sehingga admin **tidak pernah** diblokir & app milik admin bebas untuk siapa pun (blokir fungsional 402/redirect). `AppAccess` tetap satu-satunya pintu (penolakan **404**). Aksi admin-only (`/credits/deposit`, `/credits/charge`) → non-admin **404**; `POST /profile/email` (jalur utama; `POST /credits/email` dipertahankan sebagai **warisan/BC**) hanya email user login sendiri dan input non-skalar (`email[]=…`) ditolak tanpa menghapus email lama; `GET /credits/topup/return` hanya order milik user login. Callback pembayaran menerima field non-skalar sebagai **400** (bukan 500).

- **Registry server admin-only; pemilihan server lewat grant (§5.26, SPECS §6.1/§7.14)**: halaman `/servers` & seluruh aksinya menolak non-admin dengan **404** (`ServerAccess::requireManageServers()` → `AppAccessDenied`, pola `/nginx`). **Memilih** server = admin **atau** pemegang grant `server_select` (`canSelectServer()`; allowlist `server_ids`, kosong = semua); member tanpa grant hanya melihat server lokal saat create dan server yang menaungi app yang boleh ia lihat di halaman sadar-server (`visibleServers()`). Grant tidak menambah ability `AppAccess`/`BackupAccess` dan tidak membuka metrik host. Menu **Servers** disembunyikan di UI untuk non-admin (lapisan kedua; penegakan di server).
- **Seluruh permukaan agent tertutup token (§4.2/§5.21)**: `AgentAuthMiddleware` global di mode agent memeriksa bearer token (`hash_equals`) → timestamp ±60 s → nonce sekali-pakai (`NonceStore`, `flock` lintas-worker) → signature HMAC opsional; gagal apa pun ⇒ **401 tanpa detail** (tanpa oracle header mana yang salah). Tanpa `AGENT_TOKEN` route agent **tidak didaftarkan** (fail-closed → 404). Tidak ada op shell bebas: `POST /jobs` hanya menerima `op` dari daftar `DeployWorkerLauncher::MODES` (allowlist), bukan `ssh "..."`.
- **TLS agent di-pin, bukan diverifikasi biasa (§6)**: `base_url` wajib `https://`; PEM self-signed dipakai sebagai trust anchor (`TlsPinMaterializer`); `verify=false` **dilarang**; server dengan fingerprint tidak cocok **tidak disimpan**. Port agent hanya untuk IP control plane (firewall server, bukan UI).
- **Rahasia tetap lokal (§5.24)**: token agent hanya di control plane + `secrets/agent.env` server itu; env app & deploy key hidup **0600 di server itu**; `GET /apps/{id}` tidak pernah memulihkan `env`/deploy key (whitelist `APP_FIELDS`); payload job di `runtime/agent-jobs/*.json` disimpan **setelah redaksi rekursif** nilai ber-kunci sensitif; `AgentError` & `AgentArtifactMaterializer::sanitizeError()` menyaring secret dari pesan. **Satu pintu di `AgentDeployer`** (cakupannya kelas ini, **bukan** seluruh jalur pesan agent): `sanitize()` (jalur job & pesan preflight `POST /apps/check`) memakai `AgentError::sanitizeForServer($message, $this->server)` — meradaksi token, header `Authorization`/signature, **blok PEM**, dan `base_url`/host internal agent (sama dengan `MonitorController`/`FileController`/`DatabaseController`); helper privat `token()` (sanitasi) dihapus supaya tidak ada regex ganda. **Pesan yang tampil ke user** diredaksi di batas controller (bukan diserahkan ke `AgentDeployer`): `AppController::appErrorText()` (helper `agentServerDocFor()`), `NginxController::pullTemplates()`/`pullStatus()`, `BackupController::snapshots()` & `downloadDumpSql()`, serta `AgentTemplatePull` (konstruktor `array $server = []`) — semuanya lewat `AgentError::sanitizeForServer()` dan dikunci `tests/AgentErrorRedactionControllersTest.php`. **Risiko sisa (temuan pra-eksisting C-1)**: pesan yang lahir di `AgentClient::decode()`/`errorDetail()` — galat `POST /jobs` di `runJob()`/`postJob()` (mis. `stop()`/`start()`/`teardown()`) serta `pullApp()`/`appState()` — masih melewati `AgentError::sanitize()` (token/`Authorization`/signature) sehingga blok PEM/`base_url` bisa lolos ke **worker/log** (`cli/deploy.php` → `apps.error`/log deploy, `AppStopper` → log billing); perbaikan di lapisan itu terpisah dan belum diklaim selesai.
- **Env app server agent tidak pernah ditulis control plane**: nilai env hanya ada di dokumen app (metadata, diproyeksikan `AgentAppProjection::METADATA`) dan payload job `apply_env` yang dikirim lewat HTTPS ter-token (§5.23/§5.37); control plane **tidak** membuat `database/env/*` atau `apps/<name>` untuk app agent. Pesan galat jalur env tetap **tanpa nilai** (hanya nama kunci/angka baris).
- **DILARANG fallback ke `LocalDeployer`** untuk server agent — kesalahan "app remote dieksekusi lokal" adalah yang paling berbahaya. `AgentDeployer` mengimplementasikan **seluruh** `DeployerInterface` sebagai op job agent (`deploy|rebuild|rollback|apply|apply_env|stop|start|teardown`, Nginx `nginx_write|nginx_remove|nginx_reload`, SSL `ssl_issue|ssl_revoke`, §5.23/§5.27); helper `unsupported()` (`AgentError('unsupported')`) adalah jalur penolakan untuk metode baru yang belum punya padanan — **bukan** alasan meneruskan ke host lokal. `ServerResolver` melempar untuk `server_id` tak dikenal.
- **Nginx & SSL dijalankan sebagai job di server agent (§5.27, F2)**: control plane **tidak** menyalin logika/path Nginx — op `nginx_write|nginx_remove|nginx_reload|ssl_issue|ssl_revoke` menjalankan library Nginx/SSL **server itu**; perakitan vhost dibaca `GET /apps/{id}/nginx`, preflight lewat `POST /nginx/check`. Kredensial DNS tidak melintas HTTP (agent memakai berkas yang sudah ada di sana).
- **Sesi terminal & log diproxy apa adanya (§5.28, F3a)**: sesi hidup **di agent** (`DockerExec`); control plane hanya mem-proxy SSE **byte-passthrough** via Guzzle `StreamHandler` (cURL tidak bisa baca bertahap, GOTCHA §8 no. 12) dan **tidak menutup sesi agent saat klien drop** (hanya `close`/proses keluar/prune TTL). `Run` one-shot app agent **diproksi** ke agent (`TerminalController::run()` → `AgentDeployer::runCommand()` → `POST /terminal/run`, GOTCHA §8 no. 13).
- **Master compose app agent hidup di dokumen app (§5.24, GOTCHA §8 no. 14)**: `compose_content` + `host_ports` disimpan di `apps_apps` (**tidak** diproyeksikan ke agent) dan dirakit menjadi artefak job — trade-off sadar **agar tidak ada tulisan file lokal** di control plane untuk app agent; `artifacts.files` = **override port** (bukan berkas pendukung), `custom_domain` ikut `AgentAppProjection::METADATA`.
- **Rekam Error — admin-only, CSRF tanpa pengecualian (§5.43, SPECS §7.18)**: `GET /errors`, `GET /api/errors`, `GET /errors/{id}`, ubah status, dan hapus dievaluasi **admin-only → 404** (bukan 403) sebelum menyentuh store; badge nav `error_badge_count()` hanya admin + fail-safe `0`. `POST /api/errors` wajib login **dan** `_token` CSRF (tidak ada entri pengecualian di `CsrfMiddleware`); body ≤`ERROR_REPORT_MAX_BYTES` (16 KiB) dan kuota `ERROR_REPORT_RATE_PER_MIN` (20/menit per user; server per fingerprint). Urutan `CSRF → Auth` membuat POST tanpa token **dan** tanpa sesi = **419**; 401 hanya bila token sah tetapi sesi hilang. Galat penyimpanan dibalas **500 generik** tanpa detail internal. Rate limiter **fail-open** bila `kv`/DB gagal (fitur diagnostik, bukan gerbang bisnis).
- **Rekam Error — redaksi wajib, tanpa data mentah (§5.43)**: `ErrorRedactor` mengganti Bearer/Authorization/Cookie/Set-Cookie, blok PEM, URL ber-userinfo, pasangan kunci sensitif (`password|secret|token|api_key|signature|_token|csrf|…`), dan pola token (`sk-`/`ghp_`/`xox*`/JWT); context rekursif ≤5 level/50 kunci, hanya string, truncate UTF-8-safe. **TIDAK** disimpan: IP, cookie, body request, nilai env, atau `_token`; user-agent dari header dipotong 512 byte. `parent::report()` **tetap** menulis exception mentah ke `runtime/logs/webman.log` — redaksi hanya untuk salinan di `error_events`, jangan mengklaim log webman diredaksi. Mode `agent` tidak mencatat error dan tidak mendaftarkan route dashboard.
