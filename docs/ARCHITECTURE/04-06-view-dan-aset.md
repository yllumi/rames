# 4.6 Lapisan View & Aset Statis — `app/view/` + `public/`

> Bagian dari [dokumentasi arsitektur](../ARCHITECTURE.md) · Spesifikasi: [SPECS.md](../SPECS.md) · Panduan operasional: [DETAILS.md](../../DETAILS.md)

View PHP native (mesin `Raw`, tanpa build step/bundler). **Shell halaman dikelola terpusat di dua partial**: `app/view/partials/header.php` membuka `<body>` lalu menulis `<aside id="appSidebar" class="app-sidebar offcanvas-lg offcanvas-start">` (brand + `nav.sidebar-nav` + `.sidebar-user`) dan membuka `.app-main`; `app/view/partials/footer.php` menutup `</main>`, footer, lalu `</div>` penutup `.app-main`. Semua view cukup meng-`include` kedua partial — kontrak include ini **tidak berubah** saat layout berganti.

- **Halaman detail app dipecah per tab/fitur** — `app/view/app/partials/detail-*.php` (21 partial); `app/view/app/detail.php` tinggal *page shell* + indeks `include` (~185 baris): `detail-setup.php` (derivasi variabel: `$abilities`/`$canX`, overlay `$containers`, konteks compose/limits), `detail-tabs-nav.php`, `detail-tab-{info,domain,env,limits,network,db,containers,deploy,compose,access,delete}.php`, `detail-modal-{delete,guide,terminal,run,files,log}.php`, `detail-scripts-inline.php`, dan `detail-scripts.php`. Shell halaman (page-head, alert read-only, panel progres, `#app-actions`) sengaja tetap di berkas utama. Partial di-`include` dengan **scope yang sama** sehingga variabel berkas utama tetap terlihat — konsekuensinya **`partials/detail-setup.php` WAJIB include pertama** (partial lain memakai variabel turunannya) dan setiap pasangan `<?php if … ?>`…`<?php endif; ?>` harus berada di partial yang sama.
- **Metrik per-app di tab Info** — `app/view/app/partials/detail-tab-info.php` merender `<section id="app-metrics" data-app-id="…">` (3 kartu CPU/Memori/Storage dengan hook `data-metrics-value|sub|note|chart|line`) yang diisi `public/js/app-metrics.js` (dimuat `detail-scripts.php`). JS vanilla tanpa dependency: poll metrik tiap 5 dtk (maks 60 titik = 5 menit) + storage tiap 60 dtk lewat `?storage=1`, grafik = SVG `<path>` (sumbu X = **indeks titik**, bukan waktu riil), polling dijeda saat `document.hidden`, timer dibersihkan `pagehide`/`beforeunload`, hidup lagi `pageshow` (kembali dari bfcache), dan data server **hanya** ditulis via `textContent` (tanpa `innerHTML`). Alur & jebakan §5.13a.
  - **GOTCHA/WAJIB — partial adalah potong–tempel byte-exact; whitespace keluaran rapuh.** Baris include berbentuk `…; ?>` dan PHP **menelan satu newline** setelah `?>`, sehingga menambah/menghapus baris kosong di sekitar include — atau meng-indent ulang isi partial — akan **menggeser whitespace HTML** (dan `guide_html`/teks lain yang peka). Penangkal: jangan merapikan partial tanpa memverifikasi keluaran; render halaman sebelum & sesudah perubahan lalu bandingkan **byte-per-byte** (harness render di luar HTTP untuk beberapa skenario), bukan sekadar memeriksa tampilan di browser.
- **Menu dikelola di satu partial** (Apps, SSL, Volumes, Networks, Backup, Monitor, Database, Config[+ badge `update`], Users[bila admin], Servers[bila admin], Errors[bila admin, badge `open`]). **WAJIB**: view lain **tidak boleh** menyentuh/menduplikasi nav — menambah/mengubah item cukup di `partials/header.php`; state aktif lewat variabel `$active` + `aria-current="page"`. Item **Servers** hanya dirender untuk admin (`is_admin()`), konsisten dengan penegakan server (non-admin → 404).
- **Identitas brand (rebranding) — helper global satu sumber**: `app/functions.php` menyediakan `brand_name()`, `brand_logo_url()`, `brand_logo_is_custom()`; ketiganya **fail-safe** (`try/catch \Throwable` → `Rames`/`/logo-small.png`/`false`) dan **tanpa cache statik** (worker Webman persistent ⇒ nilai basi setelah brand diganti). Dipakai `app/view/partials/header.php` (judul `<title>` + brand sidebar + brand topbar mobile), `app/view/auth/login.php`, dan `app/view/index/hello.php` — semua keluaran `e()`. Form pengelolaan ada di tab **Branding** halaman Config (`app/view/nginx/partials/tab-branding.php`, presentasi murni); alur & kontraknya §5.40.
- **Halaman Servers** — `app/view/server/index.php` (daftar + status/kapabilitas) & `app/view/server/form.php` (Add/Edit server, blok PEM onboarding), aset `public/js/server.js` (uji koneksi AJAX + pengisian fingerprint). Endpoint data tanpa rahasia: `GET /api/servers`.
- **Halaman Error Log** — `app/view/errors/index.php` (daftar grup: filter status/kind/app/q, pagination, badge status) & `app/view/errors/detail.php` (metadata grup + maks 20 sampel event, stack/context sebagai teks, tombol salin, form status/hapus ber-CSRF). Keduanya set `$breadcrumbs` (`Apps → Error Log [→ Detail]`) dan `$active='errors'`; seluruh nilai dari klien dirender `e()`. `public/js/error-report.js` dimuat `partials/footer.php` **hanya bila `current_user() !== null`** (halaman login tidak melapor), tanpa dependency: listener `error`/`unhandledrejection`, throttle 10 laporan/page-load & 1/fingerprint/5 dtk, berhenti saat 419/429, `source`/`route` = pathname saja, tanpa cookie/localStorage/isi form. Alur §5.43.
- **Tema tampilan (mode gelap) — boot anti-flash + token dua lapis**: partial `app/view/partials/theme-boot.php` (meta `color-scheme` + IIFE `try/catch`) di-include **di `<head>` sebelum** stylesheet pada `partials/header.php`, `auth/login.php`, `index/hello.php`; `public/js/theme.js` (vanilla, dimuat `partials/footer.php` setelah `layout.js`) mengelola `getMode/resolve/apply/setMode`, tombol siklus `[data-theme-toggle]` (footer sidebar), radio `[data-theme-choice]` (`/profile`), listener `matchMedia`/`storage`, serta `window.ramesTheme`; `public/css/app.css` dua lapis (variabel Bootstrap + token semantik `--surface*`/`--chip-*`/`--heading-fg`/`--label-fg`/`--muted-fg`/`--grid-line`/`--tint`/`--glow-1`/`--glow-2`/`--shadow-color`/`--link-soft`/`--template-media-bg`) dengan blok `[data-bs-theme="dark"]`. Detail alur §5.42, jebakan §8 T1–T5.
- **Ikon menu = inline SVG, tanpa library ikon/CDN.** Tiap item `nav.sidebar-nav` merender `<span class="nav-ico">` (SVG line-art `viewBox="0 0 24 24"`, 18×18, `stroke="currentColor"`, `aria-hidden="true"`) lalu `<span class="nav-label">` (teks); `<a>` membawa **`data-label`** (label untuk popover rail, lihat di bawah) + `aria-label` — **bukan** `title`. Peta ikon `$__navIcons` dan `$__burger` dikumpulkan di `partials/header.php`. **DILARANG menambah library ikon/webfont/CDN** — ikon wajib inline SVG (tanpa dependensi runtime, ikut `currentColor` saat aktif/hover).
- **Lipat sidebar (desktop ≥ 992px)**: tombol `.sidebar-toggle[data-sidebar-toggle]` paling kiri `.app-sidebar-head` (kelas `d-none d-lg-inline-flex`, `aria-controls="appSidebar"`) men-toggle class **`body.sidebar-collapsed`** lewat `public/js/layout.js` (vanilla, tanpa dependensi). Kondisi rail menyempitkan `.app-sidebar` → **72px**, `.app-main { margin-left: 72px }`, menyembunyikan `.nav-label`/badge/`.brand`/`sidebar-user-*`/`.sidebar-logout`, dan memusatkan ikon. Pilihan dipersist di `localStorage['rames.sidebar']` (`'collapsed'`/`'expanded'`); skrip inline di `partials/header.php` (sebelum `<aside>`) menerapkan class **sebelum paint** (anti-flash), lalu `layout.js` menyinkronkan `aria-expanded`/`aria-label` tombol. Kegagalan `localStorage` (mode privat/storage penuh) diabaikan, bukan error.
- **Popover label menu saat rail terlipat (murni CSS, tanpa JS baru)**: di rail (≥ 992px, `body.sidebar-collapsed`) `.nav-label` disembunyikan, jadi tiap `a.nav-link` membawa **`data-label`** yang dirender ulang sebagai *popover* lewat `content: attr(data-label)` pada `.nav-link::after` (bubble ke kanan ikon; `left: calc(100% + 10px)`, `white-space: nowrap`) ditambah `.nav-link::before` (panah kecil penunjuk ikon). Popover tampil saat **`:hover`** dan **`:focus-visible`** (transisi `opacity .14s ease` + geser `translateX`), `pointer-events: none`, `z-index: 1080` (**relatif di dalam stacking context `.app-sidebar`** — bukan nilai efektif global; lihat sub-bullet berikut).
  - **`z-index: 1030` pada `.app-sidebar` (≥ 992px) WAJIB.** Popover (`.nav-link::after`) berada di dalam stacking context `.app-sidebar`; tanpa `z-index` pada elemen sidebar (semula `auto`), card/konten `.app-main` yang datang **belakangan di DOM** melukis **di atas** sidebar sehingga popover (dan sidebar) terhalang. Nilai `1030` = layer "fixed" Bootstrap: di atas seluruh konten halaman, **di bawah** `.offcanvas` (`1045`) dan `.modal` (`1055`) agar dialog tetap menutupi sidebar. **Lever-nya adalah `z-index` elemen `.app-sidebar`, bukan `::after`** — `z-index: 1080` pada `::after` hanya berlaku relatif di dalam stacking context sidebar, jadi ia **tidak** dapat mengangkat popover melewati card `.app-main`. Aturan ini **hanya** berlaku di dalam `@media (min-width: 992px)`; drawer offcanvas mobile (< 992px) tidak terpengaruh.
  - **`body.sidebar-collapsed .sidebar-nav { overflow: visible; }` WAJIB.** `.sidebar-nav` adalah satu-satunya elemen peng-clip di jalur rail (`overflow-y: auto`; `.offcanvas-lg` pada ≥ lg tidak menyetel `overflow`), sedangkan popover menggantung ke kanan melewati rail 72px — tanpa `overflow: visible` popover terpotong. `overflow` **hanya** dilonggarkan di mode rail; saat sidebar terbuka nilainya tetap `auto` (menu tetap scrollable) dan popover tidak dirender.
  - `@media (prefers-reduced-motion: reduce)` mematikan transisi `::before`/`::after` (bersama transisi `width`/`margin-left` shell).
- **Burger mobile (< 992px)**: `.sidebar-burger` di **kiri** topbar (`<button data-bs-toggle="offcanvas" data-bs-target="#appSidebar">`) membuka drawer offcanvas via `bootstrap.bundle.min.js` — **tanpa JS kustom**.
- **Topbar mobile**: `<header class="topbar sticky-top d-lg-none">` (brand + tombol hamburger di atas) hanya tampil < 992px.
- **Responsif**: komponen Bootstrap `offcanvas-lg offcanvas-start` — < 992px sidebar menjadi **drawer offcanvas**; ≥ 992px (`@media (min-width: 992px)` di `public/css/app.css`) sidebar `position: fixed` selebar **264px** dan `.app-main` digeser `margin-left: 264px`. Tanpa library/JS baru (`bootstrap.bundle.min.js` sudah dimuat).
- **Gaya & aset**: kelas `.app-sidebar`/`.app-sidebar-head`/`.sidebar-nav`/`.sidebar-user`/`.sidebar-user-name`/`.sidebar-user-badge`/`.sidebar-logout`/`.app-main`/`.nav-ico`/`.nav-label`/`.sidebar-toggle`/`.sidebar-burger`/`.brand-text` di `public/css/app.css`; `.topbar`/`.brand`/`.avatar`/`.footer` dipertahankan (`.topbar` kini khusus topbar mobile). Transisi `width`/`margin-left` **`.18s ease`**, dimatikan `@media (prefers-reduced-motion: reduce)`. JS: `public/js/layout.js` (dimuat di `partials/footer.php`) + `app-terminal.js`/`app-files.js`/`app-metrics.js`/`backup.js`/`monitor.js`/`update.js` per halaman. Aset gambar template (logo) ada di `public/images/templates/` — peta `slug → ekstensi` dari `template_logo_map()` (§5.1c), kelas `.template-tile-logo`/`.template-logo-card`/`.template-logo-inline`. Mengubah layout = sentuh kedua partial + CSS/JS, **bukan** 20 view.
  - **WAJIB — naikkan `?v=N` setiap mengubah `app-terminal.js`/`app-files.js`/`app-metrics.js`.** Gejala: JS baru sudah di disk tetapi browser tetap memakai versi lama (perilaku fitur tidak berubah walau hard refresh tidak selalu cukup, mis. ter-cache agresif/proxy). Sebab: `app/view/app/partials/detail-scripts.php` memuat `<script src="/js/app-terminal.js?v=N">`/`app-files.js?v=N` — query `?v=` adalah **satu-satunya** cache-buster (tanpa hash/nama ber-hash di URL). Penangkal: **setiap** perubahan `public/js/app-terminal.js`, `app-files.js`, atau `app-metrics.js` **wajib** menaikkan `?v=` di `detail-scripts.php` (versi saat ini: `app-terminal.js?v=7`, `app-files.js?v=4`, `app-metrics.js?v=2`); file JS/CSS lain tanpa `?v=` cukup hard refresh.
- **Breadcrumb — partial `app/view/partials/breadcrumb.php` (presentasi murni, satu sumber kebenaran).** Partial membaca variabel **`$breadcrumbs`** = array item berbentuk `['label' => string, 'href' => string|null]`; item **terakhir** = halaman aktif → dirender **tanpa** tautan (`href => null`) + `aria-current="page"` dan class `.active`; item lain ber-`href` menjadi `<a>`. Semua label/href lewat `e()`. Markup: `nav[aria-label="Breadcrumb"]` → `ol.breadcrumb` (komponen Bootstrap) berisi `li.breadcrumb-item`. **Titik render**: `partials/header.php` meng-include partial ini **tepat setelah `<main class="container-fluid …">` dan sebelum blok flash**, hanya bila `!empty($breadcrumbs)` — kontrak include `<main>`/`.app-main` **tidak berubah**, dan halaman tanpa `$breadcrumbs` tidak menampilkan breadcrumb. Karena variabel view berbagi scope dengan include, halaman cukup men-set `$breadcrumbs` **sebelum** `include …/partials/header.php`.
- **Gaya `.breadcrumb`** di `public/css/app.css` (`font-size: 12.5px`; divider `›` lewat `--bs-breadcrumb-divider: "\203A"`; `--bs-breadcrumb-item-padding-x: .5rem`; `--bs-breadcrumb-margin-bottom: 0`): tautan warna sekunder (`--bs-secondary-color`) → hover/focus-visible `--accent2`; item `.active` warna `--bs-body-color` + tebal. Memakai variabel Bootstrap dan **tidak** menyentuh `.page-head`.
- **Penggantian tautan back tingkat halaman**: tautan "kembali ke induk" (mis. `← Daftar Apps`, `← Apps`, `← Daftar Database`, `← Networks`, `← Detail app`, `← Semua Template`, `← Kembali ke Apps`) **dihapus** dan digantikan breadcrumb. **Form-action** `Batal`/`Kembali` **di dalam form tetap** (bagian alur form, bukan navigasi hierarki). Halaman **tanpa** breadcrumb (tidak punya tautan ke induk): `/apps`, `/database`, `/users`, `error/404`. Tautan nav wizard (item `$breadcrumbs`, tab mode, **Batal**/**Kembali**) boleh dibangun helper view yang menambahkan `?server_id=` (preselect saja, §5.22) bila server terpilih bukan `local` — item `$breadcrumbs` tetap berbentuk `['label', 'href']` dan tetap dirender lewat `e()`.

> **WAJIB — halaman ber-breadcrumb men-set `$breadcrumbs` sebelum `include …/partials/header.php`, dan item terakhir (halaman aktif) ber-`href => null`.** Gejala: breadcrumb tidak tampil, atau item aktif muncul sebagai tautan yang bisa diklik ke dirinya sendiri. Sebab: partial hanya dirender bila `!empty($breadcrumbs)`, dan posisi aktif ditentukan dari **urutan array** (`array_key_last`), bukan dari `href`. Penangkal: set array lengkap (item induk ber-`href`, item terakhir `href => null`) di atas `include` header; jangan bergantung pada `$breadcrumbs` yang mungkin di-set halaman lain.
> **GOTCHA — jangan menyisakan kolom kanan `page-head` kosong saat tombol opsional tak dirender.** Gejala: `page-head` tampak berlubang/tidak seimbang ketika tombol Panduan (atau tombol log) tidak ada, karena `<div>` pembungkus tombol tetap tercetak walau isinya kosong. Sebab: breadcrumb menggantikan tautan back, sehingga `page-head` pada sebagian halaman hanya punya tombol opsional di kolom kanan. Penangkal: bungkus kolom kanan itu dengan kondisi — sudah dilakukan di `app/view/app/detail.php` (`if ((($guideHtml ?? '') !== '') || ($logContainer !== null && $logContainer !== ''))`) dan `app/view/app/template.php` (`if (($guide_html ?? '') !== '')`).
> **DILARANG — menambah CDN/library breadcrumb.** Breadcrumb wajib memakai komponen Bootstrap (`nav`/`ol.breadcrumb`) + CSS tema di `public/css/app.css`; jangan menarik library/plugin breadcrumb dari CDN atau bundler baru.

> **WAJIB — semua aturan `body.sidebar-collapsed` tetap di dalam `@media (min-width: 992px)`.** Gejala: di layar < 992px drawer offcanvas menyempit/menghilangkan label, atau `.app-main` tiba-tiba di-dorong `margin-left: 72px`. Sebab: pada mobile `.app-main` mengikuti alur normal (bukan `position: fixed`), sehingga aturan rail yang bocor merusak layout. Penangkal: setiap selector `body.sidebar-collapsed …` hanya di dalam blok `@media (min-width: 992px)`, termasuk yang menyembunyikan `.nav-label`, aturan popover (`::before`/`::after`, `content: attr(data-label)`), dan `overflow: visible` pada `.sidebar-nav`.
> **GOTCHA — rail 72px menyembunyikan teks via `display: none`, bukan menghapus `<a>`.** Karena `.nav-label` di-`display: none` saat rail, link **wajib** mempertahankan `aria-label` agar ikon tetap punya nama aksesibel; SVG tetap `aria-hidden="true"`/`focusable="false"` agar ikon tidak diumumkan ganda. **WAJIB**: label popover diambil dari **`data-label`** (bukan `title`) — memakai `title` akan memunculkan **tooltip native + popover CSS sekaligus** (tooltip ganda) saat hover.
> **GOTCHA — jangan turunkan/naikkan `z-index` `.app-sidebar` melewati `1045` (offcanvas) / `1055` (modal).** Gejala: rail/popover menimpa latar dialog sehingga dialog tidak lagi menutupi sidebar. Sebab: nilai > `1045` mengangkat stacking context sidebar di atas layer offcanvas/modal Bootstrap. Sebab lain (arah turun): menghapus/menaikkan ke `auto` mengembalikan bug popover terhalang card `.app-main`. Penangkal: **pertahankan `1030`** — cukup untuk mengangkat sidebar di atas konten halaman, tetap di bawah dialog.
